# PRD — Tiberbu CRM Visual Consistency Pass
**Status:** Draft · **Author:** Salim · **Date:** 2026-08-03
**Branch:** `careverse_fixes`

---

## 1. Problem Statement

The Tiberbu CRM has two visually disconnected surfaces:

| Surface | Files | Visual character |
|---|---|---|
| **www/ pages** (login, home, access-restricted) | `crm/www/*.html` + `crm/public/css/tiberbu-brand.css` | Rich glassmorphism: radial-gradient scene, dark brand panel, glass cards, blur+saturate, dot-grid texture, entry animations, tight typographic hierarchy |
| **SPA interior** (all Vue pages post-login) | `frontend/src/` | Flat frappe-ui defaults: plain `bg-surface-base` canvas, no scene depth, no glass, minimal typographic hierarchy, unstyled header (`border-b` only), unstyled sidebar (`bg-surface-gray-1`) |

A user logs in through a polished, branded experience and immediately lands in a visually plain app. The brand promise set by the login page is not sustained. This PRD defines what to change and what to leave alone.

---

## 2. Goals

1. **Perceptual continuity** — the app interior should feel like it shares a design language with the login and home pages.
2. **Dark/light parity** — every visual addition must resolve correctly in both `[data-theme="dark"]` and `:root` (light). The www pages are currently light-only; that is out of scope here.
3. **Minimal surface area** — changes land in CSS and the layout shell. No rewrites of page or feature components.
4. **Zero regressions** — frappe-ui token semantics must not be broken; all existing `text-ink-*`, `bg-surface-*`, `border-outline-*` usages continue to work.

---

## 3. Out of Scope

- Any changes to feature logic, DocType rendering, list views, kanban, or form pages.
- Adding dark mode to www/ pages.
- Typography changes inside page-level components (those are owned by frappe-ui and custom component teams).
- Mobile layout (`MobileLayout.vue`) — addressed separately.
- The `tiberbu-brand.css` file itself — it already represents the target state.

## 4. Brownfield Audit

### 4.1 Token System (what exists)

The SPA already has two layers of tokens:

**Layer 1 — frappe-ui semantic tokens** (generated by `colorPalette.js`, emitted into `frappe-ui/style.css`)
- Full gray ramp: `--surface-gray-{1..10}`, `--ink-gray-{1..10}`, `--outline-gray-{1..10}`
- Full blue→red accent ramp (overridden in `frontend/src/index.css`): `--surface-blue-*`, `--ink-blue-*`, `--outline-blue-*`
- Both `:root` (light) and `[data-theme="dark"]` blocks present

**Layer 2 — www/ tokens** (in `tiberbu-brand.css` and inline login/home styles)
- `--brand`, `--brand-dark`, `--brand-tint-{07,10,12}`
- `--brand-ring`, `--brand-shadow`
- `--glass-bg`, `--glass-strong`, `--glass-border`, `--glass-shadow`, `--glass-inset`
- `--radius`, `--radius-sm`
- `.t-h1`, `.t-h2`, `.t-label`, `.t-prose`, `.t-btn-primary`, `.t-card`, `.t-scene`

**Gap:** Layer 2 tokens and utilities are not available inside the SPA. They must be ported into `frontend/src/index.css` so they resolve in both light and dark mode.

### 4.2 Layout Shell (what exists)

```
DesktopLayout.vue
├── div.flex.h-screen.w-screen
│   ├── AppSidebar (div.relative.flex.h-full.bg-surface-gray-1)
│   │   └── Sidebar (border-r border-outline-gray-1)
│   └── div.flex-1.flex.flex-col.h-full.overflow-auto.bg-surface-base
│       ├── AppHeader (div.flex.border-b.pr-5)
│       │   └── #app-header teleport target + CallUI
│       └── <slot />  ← page content
```

**Gaps identified:**

| Element | Current | Target |
|---|---|---|
| Sidebar background | `bg-surface-gray-1` (flat off-white / near-black dark) | Retains base but gains subtle scene depth via top-glow CSS |
| Sidebar logo / user area | No brand mark visible in collapsed rail | Brand red mark visible at all widths |
| Header | `div.flex.border-b.pr-5` — no visual weight | Frosted glass strip: `backdrop-filter: blur(12px)`, translucent bg, stronger bottom border |
| Page canvas | `bg-surface-base` (pure white / dark) | Light: soft top-left red ambient glow. Dark: remains near-black with very faint red haze |
| Typography in headers | frappe-ui defaults (no letter-spacing) | `LayoutHeader` left slot gets heading treatment matching `.t-h1` sizing / tracking |
| Focus rings | Invisible (no ring on interactive elements in SPA) | Port `var(--focus)` from www/ — 3px brand-ring shadow on `:focus-visible` |
| Scroll chrome | Default browser | Thin, neutral, matching surface colors |

## 5. Acceptance Criteria

### AC-1: Token layer parity
- All `--brand-*`, `--glass-*`, `--radius`, `--radius-sm`, `--focus` tokens defined in `:root` and `[data-theme="dark"]` blocks inside `frontend/src/index.css`.
- `tiberbu-brand.css` does NOT change (it is the source of truth for www/).

### AC-2: Sidebar scene
- Light mode: the sidebar column has a very faint radial red gradient at the top (`rgba(188,24,35,0.06)`), creating depth without changing the text surface.
- Dark mode: same glow but with the dark brand tint so the black surface isn't flat.
- The `border-r border-outline-gray-1` rule must be preserved.
- No change to sidebar item text colors, active states, or hover states.

### AC-3: Glass header strip
- `AppHeader.vue` gains a CSS class (or inline style block in `<style scoped>`) that applies:
  - `background: var(--glass-bg)`
  - `backdrop-filter: blur(12px) saturate(140%)` + `-webkit-` prefix
  - `border-bottom: 1px solid var(--glass-border-color)` (new token: `rgba(0,0,0,0.08)` light, `rgba(255,255,255,0.07)` dark — distinct from the opaque `border-outline-gray-1` used on sidebar)
  - `position: sticky; top: 0; z-index: 10`
- Fallback when `backdrop-filter` unsupported: `background: var(--surface-gray-1)` (current value, no regression).
- Dark mode: glass tokens resolve correctly via `[data-theme="dark"]`.

### AC-4: Page canvas ambient scene
- `DesktopLayout.vue` content column (`div.flex-1...`) adds a background:
  ```css
  background:
    radial-gradient(55% 40% at 15% 0%, var(--brand-tint-07) 0%, transparent 60%),
    var(--surface-base);
  ```
  where `--surface-base` is already the frappe-ui `bg-surface-base` resolved color.
- This must NOT use `background-attachment: fixed` (breaks in Safari with `overflow: auto`).
- Dark mode: `--brand-tint-07` dark value produces the haze; the near-black base remains dominant.

### AC-5: Focus ring
- `:where(a, button, [role="button"], input, select, textarea):focus-visible` in `index.css` gets:
  ```css
  outline: none;
  box-shadow: var(--focus);
  border-radius: var(--radius-sm);
  ```
- Does not override components that already set their own focus style via frappe-ui (check for `:focus-visible` in `frappe-ui/style.css` before shipping).

### AC-6: Scrollbar styling
- Custom scrollbar for webkit browsers:
  ```css
  ::-webkit-scrollbar { width: 6px; height: 6px; }
  ::-webkit-scrollbar-track { background: transparent; }
  ::-webkit-scrollbar-thumb { background: var(--outline-gray-3); border-radius: 3px; }
  ::-webkit-scrollbar-thumb:hover { background: var(--outline-gray-4); }
  ```
- Firefox: `scrollbar-width: thin; scrollbar-color: var(--outline-gray-3) transparent` on `html`.

### AC-7: Typography heading treatment
- Add a `.crm-page-title` utility class (not Tailwind) in `index.css`:
  ```css
  .crm-page-title {
    font-weight: 600;
    letter-spacing: -0.02em;
    line-height: 1.15;
    color: var(--ink-gray-9);
  }
  ```
- Apply it to `ViewBreadcrumbs.vue` breadcrumb label only (the active/last crumb). This is the single highest-traffic heading across all list pages.
- No changes to font-size — keep frappe-ui's `text-2xl` or existing size classes.

### AC-8: No hardcoded hex colors
- Grep for `#[0-9a-fA-F]{3,8}` in every file touched. All instances must be either:
  - Pre-existing (not introduced by this work), or
  - Token definitions in `index.css` `:root` / `[data-theme="dark"]` blocks.

### AC-9: Build passes
- `pnpm build` from `frontend/` exits 0 with no warnings.
- `tsc --noEmit` passes.
- Manual browser check: light mode + dark mode, both verified by screenshot.

## 7. Visual Design Spec

### Sidebar (AC-2)

```
Light mode
──────────────────────────────
bg: --surface-gray-1  (unchanged, ~#f9f9f9)
top glow: radial-gradient(70% 30% at 50% 0%,
            rgba(188,24,35,0.06) 0%, transparent 55%)
border-right: 1px solid --outline-gray-1

Dark mode
──────────────────────────────
bg: --surface-gray-1  (dark token, ~oklch(0.239,0,0) = near-black)
top glow: radial-gradient(70% 30% at 50% 0%,
            rgba(210,58,65,0.09) 0%, transparent 55%)
border-right: 1px solid --outline-gray-1
```

### Header strip (AC-3)

```
Light mode
──────────────────────────────
bg: rgba(255,255,255,0.62)   (--glass-bg)
backdrop-filter: blur(12px) saturate(140%)
border-bottom: 1px solid rgba(0,0,0,0.08)
position: sticky; top: 0; z-index: 10

Dark mode
──────────────────────────────
bg: rgba(30,30,30,0.55)      (--glass-bg dark)
backdrop-filter: blur(12px) saturate(140%)
border-bottom: 1px solid rgba(255,255,255,0.07)
```

### Page canvas (AC-4)

```
Light mode
──────────────────────────────
background:
  radial-gradient(55% 40% at 15% 0%,
    rgba(188,24,35,0.07) 0%, transparent 60%),
  #fff;  ← resolves to --surface-base

Dark mode
──────────────────────────────
background:
  radial-gradient(55% 40% at 15% 0%,
    rgba(210,58,65,0.08) 0%, transparent 60%),
  oklch(0.168 0 0);  ← resolves to --surface-base dark
```

The gradient uses inline values (not CSS var) for the rgba portion because `var()` inside `radial-gradient()` using alpha tokens requires the token to be a full `rgba(...)` string — which it is for `--brand-tint-07`, so using the token IS valid.

## 8. Risks & Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| `backdrop-filter` breaks Safari overflow scroll | Low | The header is `sticky` in a scrolling container — test in Safari WebKit explicitly. Fallback: solid `bg-surface-gray-1`. |
| Radial gradient on content column breaks kanban/calendar full-bleed | Low | Gradient is `at 15% 0%` (top-left) with `transparent 60%` — won't visually clash with content area; kanban/calendar use their own inner scroll containers. |
| `background` shorthand on `.flex-1` overrides `bg-surface-base` Tailwind class | Medium | Use a scoped `<style>` block in `DesktopLayout.vue` with a selector that wins over Tailwind utilities, or apply via a CSS class added in `index.css` with higher specificity. |
| Focus ring doubles with frappe-ui's own focus style on `Button`, `Input` | Low | Check `frappe-ui/style.css` for any `:focus-visible` declarations before shipping AC-5. If overlap, scope the rule to exclude `.frappe-button`. |
| Dark mode glass tokens look too light/dark at actual contrast levels | Medium | Manual screenshot review at both themes required per AC-9. Adjust rgba alpha values as needed. |
